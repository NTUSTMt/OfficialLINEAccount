# 幹部頁面功能擴充設計文件

## 1. 意圖與緣由 (Intent & Why)
台科登山社幹部在管理活動與審核報名名冊時，面臨三大業務瓶頸：
1. **名單審核耗時且難以客觀衡量**：各活動的路線難度與天數不同，幹部需要逐一閱讀每位報名者的體能自述與過往登山經歷。在報名人數眾多時，人工評估效率低且容易因人情因素偏頗。同時，直接將含有報名者個人身分資訊的資料交給外部 AI 存在嚴重的隱私與個資洩漏風險。
2. **國際化活動雙語文案維護成本高**：為吸引國際學生參與，活動需提供英文版本。然而幹部手動翻譯中文活動簡介與分天行程費時，且容易因字數超標或時間序列格式紊亂而破壞系統 UI 顯示。
3. **名單表格編輯與分組視覺化不足**：既有名單表格缺乏欄位與列的色彩區隔功能，且修改備註或審核狀態需要頻繁開啟側邊抽屜，操作流暢度有待提升。

本專案旨在透過引進去識別化 AI 輔助與前端進階表格自訂能力，大幅提升幹部作業效率與資料安全性。

---

## 2. 目標、非目標與反目標 (Goals, Non-goals, Anti-goals)

### 目標 (Goals)
- **AI 體能與經驗綜合排序**：
  - 發送資料前嚴格去識別化（完全剝除姓名、電話、學號、Line ID 等個資，僅傳遞虛擬序號）。
  - 對象為當前活動之「所有有效報名者（排除已取消者）」。
  - 結合當前活動的路線難度、天數與負重需求，由 AI 產出 0 至 100 分之綜合適合度評分與具體評估理由（Reasoning）。
  - 於名單表格原地整合呈現，支援一鍵依 AI 分數重新排序。
  - 評估結果依 `eventId` 暫存於 `localStorage`，重新整理不遺失，並提供「重新評估」按鈕。
- **活動內容 AI 一鍵雙語翻譯**：
  - 一鍵將活動中文標題、簡介與行程翻譯為英文，直接填入表單英文欄位並提供還原功能。
  - 嚴格限制總字數 ≤ 1400 字元。
  - 格式嚴格鏡像對應中文版（分天結構、時間箭頭 `→` 與高山地名對齊）。
- **名單表格橫縱向雙向色彩與原地編輯**：
  - 縱向（欄）與橫向（列）工具內嵌純色圓圈，點擊展開 6 色選擇器（藍、綠、黃、橘、紫、灰），設定標頭與微底色。
  - 介面極簡，不顯示「選擇顏色：」等文字，直覺點選。
  - 支援儲存格原地編輯審核狀態與幹部備註（Enter/onBlur 靜默儲存，不跳提示）。
  - 色彩與表格偏好按活動持久化儲存於 `localStorage`。
  - 100% 完整保留現有名單表格所有功能（排序、縮放、隱藏、凍結、搜尋、篩選、推播、查看證件與個人檔案、匯出等）。

### 非目標 (Non-goals)
- 不取代幹部最終審核權：AI 僅提供適合度分數與排序建議，不會自動將報名者直接寫入正取或備取至資料庫，仍由幹部自主決定。
- 不修改報名表填寫前台（LIFF 前端報名流程）。
- 不變更既有資料庫 Schema（現有 `event_signups` 與 `members` 欄位已完整支援備註與各項經歷）。

### 反目標 (Anti-goals)
- 嚴禁讓 AI 存取任何 PII（個人識別資訊）。
- 嚴禁在前端暴露 Gemini API 金鑰。
- 嚴禁破壞或遺忘名單表格既有功能。
- 嚴禁在儲存備註時彈出干擾性的 Toast 提示視窗。

## 3. 系統限制與邊界條件 (Constraints)
- **安全性與隱私規範**：遵循專案與法規隱私要求，個資必須於前端過濾後才送出，後端亦做第二道過濾檢查。
- **字數限制**：總字數上限 1400 字元。
- **環境與連線**：使用後端 Supabase Edge Function（Deno）調用 Gemini API，金鑰儲存於 Supabase Secret（`GEMINI_API_KEY`）。
- **相容性**：前端使用既有 Vite + React + TypeScript + Lucide-react 架構，套件管理依循 pnpm。

---

## 4. 架構方案評估 (Approaches)

### 方案一（已獲使用者確認採用）：Supabase Edge Function 架構
- **做法**：於現有 `notify-dispatcher` Edge Function 中擴充 `ai_evaluate_applicants` 與 `ai_translate_event` 兩項 action，前端統一透過 `callDispatcherAction` 呼叫。`WebAdminRoster` 與 `WebAdminEvents` 擴充對應 UI。
- **優點**：安全性最高（金鑰不外洩）、直接復用既有 CORS 控管、幹部身分驗證與稽核日誌，省去額外部署配置的維護負擔。
- **權衡**：需在 `notify-dispatcher` 中新增 AI 處理邏輯與單元測試。

### 方案二：前端直連 Gemini API（已排除）
- **原因**：前端直接呼叫會暴露金鑰，若由使用者手動輸入又增加操作負擔，安全性與隱私控管脆弱。

### 方案三：GAS Worker 轉發（已排除）
- **原因**：GAS 執行緩慢、冷啟動延遲顯著，易因連線逾時導致操作中斷，且與專案直通 Supabase 之架構方針不符。

## 5. 詳細設計與決策 (Detailed Design Decisions)

### 5.1 AI 體能與登山經驗去識別化評估
1. **去識別化封包結構**：
   - 前端提取報名清單，排除 `status === '已取消 Cancelled'`，過濾剔除 `name`、`line_id`、`phone`、`email`、`student_id`、`id_card`、`emergency_contact_*` 等個人識別欄位。
   - 僅保留虛擬序號（`anonymousId`: `A1`, `A2`...）、`outdoor_experience`、`fitness_desc`、`medical_history`（去識別化後之病史描述）。
   - 隨附當前活動資訊：`title`、`start_date`、`end_date`、`duration_days`、`summary`、`itinerary`。
2. **分批機制（Batching）**：
   - 若有效報名人數超過 30 人，前端自動以 25 人為一組分批送出請求並合併回傳結果，避免超出單次 Prompt Output Token 限制與 Edge Function 60 秒超時。
3. **AI 結構化輸出規範**：
   - Edge Function 要求模型以 JSON 輸出：
     ```json
     {
       "evaluations": [
         {
           "anonymousId": "A1",
           "score": 88,
           "rating": "高度適任",
           "reasoning": "具備百岳重裝過夜經驗，每週有規律有氧運動，足以應付二日高山行程負重與陡坡。"
         }
       ]
     }
     ```
4. **表格原地呈現與排序**：
   - 前端接收後將 `anonymousId` 映射回對應報名者資料列。
   - 在名單表格中顯示「AI 適合度」與「評估理由」欄位。
   - 點擊「依 AI 分數排序」時，直接依據 `score` 由大至小重新排列當前名單畫面。
5. **持久化快取**：
   - 評估結果儲存於 `localStorage`（鍵名 `wa_roster_ai_evaluations_v1_${eventId}`），頁面重新整理或切換分頁後依然保留。
   - 介面提供「重新評估」按鈕供幹部手動刷新最新結果。

### 5.2 活動內容 AI 一鍵雙語翻譯
1. **輸入與約束**：
   - 輸入中文活動名稱（`title`）、簡介（`summary`）、行程（`itinerary`）。
   - 系統提示詞嚴格規範：
     - `title_en`：精簡英譯。
     - `summary_en`：語氣客觀清楚。
     - `itinerary_en`：逐日對應中文行程，嚴格保留 `Day X: HH:MM ... → ...` 格式與各站點對齊。
     - 總字數限制 ≤ 1400 字元。
2. **套用與還原**：
   - 翻譯完成後直接將值填入 `title_en`、`summary_en`、`itinerary_en` 之輸入欄位。
   - 保留前次內容快照，提供「一鍵還原」按鈕，幹部亦可直接在欄位中編輯修改。

### 5.3 名單表格自訂色彩與原地編輯
1. **雙向色彩（橫向列與縱向欄）**：
   - 縱向欄位：標頭右側放置圓形按鈕，點擊展開微型調色盤（6 色圓點：灰/藍/綠/黃/橘/紫，純色圓點無文字）。選色後標頭與儲存格套用微底色與頂部邊框。
   - 橫向列：序號（`#1`）右側放置圓形按鈕，點擊展開同款 6 色調色盤。選色後該列左側加上對應色條，整列套用微底色。
   - 顏色規格：
     - 灰（預設）：`#f8fafc` / 邊框 `#cbd5e1`
     - 藍：標頭 `#bae6fd` / 儲存格微底色 `rgba(56, 189, 248, 0.08)` / 邊框 `#0284c7`
     - 綠：標頭 `#bbf7d0` / 儲存格微底色 `rgba(74, 222, 128, 0.08)` / 邊框 `#16a34a`
     - 黃：標頭 `#fde68a` / 儲存格微底色 `rgba(250, 204, 21, 0.10)` / 邊框 `#ca8a04`
     - 橘：標頭 `#fed7aa` / 儲存格微底色 `rgba(251, 146, 60, 0.08)` / 邊框 `#ea580c`
     - 紫：標頭 `#e9d5ff` / 儲存格微底色 `rgba(192, 132, 252, 0.08)` / 邊框 `#9333ea`
   - 衝突層疊：當直欄與橫列皆套用色彩時，儲存格透過半透明透明度自然混合，文字顏色維持最高可讀性對比。
   - 持久化儲存：偏好儲存於 `localStorage` 之 `wa_roster_table_prefs_v1`（以 `eventId` 索引），重整或下次進入時自動復原。
2. **原地直接編輯 (Inline Editing)**：
   - 審核狀態（`status`）：提供原地 Select 下拉選單，變更時立即寫入 Supabase `event_signups` 表。
   - 幹部備註（`notes`）：提供原地 Text Input，使用者編輯後於 `onBlur` 或按下 `Enter` 鍵時自動儲存。
   - 靜默儲存：成功時不顯示任何彈窗提示；若失敗則透過既有錯誤機制警示。
3. **既有功能保護**：
   - 嚴格保留既有之欄位縮放、欄位拖曳重排、欄位隱藏、左側凍結、文字搜尋、狀態篩選、推播發送、查看證件、會員檔案 Modal 及匯出 Google Sheets 等功能。
